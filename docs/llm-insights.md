# CreatorLens LLM 证据化洞察

> Phase 5 · LLM 集成架构、Prompt 设计、校验与降级策略

## 架构

```
Phase 4 统计结果 + 维度分析 + 规则洞察
          ↓
    策略知识检索（Top 3）
          ↓
   buildLLMContextData() → 结构化上下文 JSON
          ↓
   generateLLMInsights() → OpenAI 兼容 API 调用
          ↓
   validateLLMInsights() → 事实一致性校验
          ↓
   ┌─ 通过 → LLM 洞察替换规则洞察 → 报告页展示（AI Badge）
   └─ 失败 → 降级到 Phase 4 规则洞察 → 报告页展示（规则引擎 Badge）
```

## Prompt 设计

### 四段式结构

1. **角色与约束**：明确 LLM 是数据分析助手，必须遵守的规则（不编造数字、审慎表达、不使用因果断言）
2. **账号统计数据**：服务端计算的统计事实（JSON），包括核心指标、维度分析摘要、规则洞察
3. **策略知识卡片**：Top 3 检索结果（标题、策略内容、匹配原因）
4. **输出格式要求**：严格的 JSON Schema

### 安全约束

**发送给 LLM 的数据**：
- 预先计算的汇总统计（均值、中位数、计数）
- 维度分析结果（分组标签、样本量、中位数）
- Top 3 检索策略卡片
- 项目元数据（品类、人群、目标）

**绝不发送**：
- 原始 Excel/CSV 数据
- 视频文件 URL 或用户 PII
- 系统配置信息
- 前端派生指标

## API 配置

| 环境变量 | 说明 | 默认值 |
|----------|------|--------|
| `LLM_API_KEY` | OpenAI 兼容 API 密钥 | — |
| `LLM_MODEL` | 模型名称 | `gpt-4o-mini` |
| `LLM_BASE_URL` | API endpoint | `https://api.openai.com/v1` |

密钥仅通过 `process.env` 读取，不写入代码、不提交仓库、不传输到浏览器、不输出到日志。

## 错误处理与降级

| 错误类型 | 行为 |
|----------|------|
| 无 `LLM_API_KEY` | 跳过 LLM，使用规则洞察 |
| 网络超时（15s） | 重试 1 次，仍失败则降级 |
| HTTP 4xx | 不重试，直接降级 |
| HTTP 5xx | 重试 1 次，仍失败则降级 |
| JSON 解析失败 | 降级 |
| 响应缺少必填字段 | 跳过该条，其他洞察仍可使用 |
| 返回空 `insights` | 保留规则洞察 |

## 事实一致性校验

校验层 `validateLLMInsights()` 在 LLM 响应解析后立即执行：

1. **ID 存在性**：`metric_evidence_ids` ⊆ 规则洞察 ID 集合；`knowledge_card_ids` ⊆ 检索结果 ID 集合
2. **数值合法性**：无 NaN/Infinity，样本量 > 0
3. **因果断言检查**：禁止"证明了""一定会""导致""必然"等词汇
4. **结构完整性**：必填字段非空
5. **知识引用一致性**：无知识命中时 `knowledge_card_ids` 必须为空

任一条不通过 → 该条洞察丢弃。全部不通过 → 降级到规则洞察。

## 降级保障

三级降级链：
1. 无 API key → 规则洞察
2. LLM 调用异常 → 规则洞察（保留完整 Phase 4 统计和检索结果）
3. 校验失败 → 规则洞察（记录失败原因到快照）

降级时报告页显示"AI 增强暂不可用，展示规则洞察"。

## 可追溯性

每次分析保存 `AnalysisSnapshot`：
- 检索输入和命中卡片 ID
- LLM 模型和 Prompt 版本
- 生成洞察数量和校验通过数量
- 降级原因（如有）

同一 analysisId 的结果可完整追溯到：原始数据 → Phase 4 统计 → 检索结果 → LLM 上下文 → 校验结果。
